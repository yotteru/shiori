## 決定事項（理由つき・最終状態のみ）
- 入口は「しおり」タブ（今日／明日／週をいつでも切り替え。下のボタンか横スライド）。時間帯で画面を切り替えない — 理由：時間で中身が変わると戸惑った
- 今日・明日は縦のカレンダー。予定は最小30分・15分刻み、選んでドラッグで移動・上下の丸で伸縮 — 理由：入れた順ではなく自由に組みたい
- 左列は「いつもの固定」（設定で曜日つき。変更は今日以降すべてに反映、その日に変えたものは優先） — 理由：平日・休日で固定が違い、日によって例外がある
- よく使う操作は画面の下半分に（候補・主な操作・＋ボタン・今日｜明日｜週）。上は日付と今週の合計だけ。カレンダーの見える範囲は狭くしない — 理由：iPhone を片手で持つと下半分しか届かない
- スクロールはページ全体で1本。見出し（日付と今週の合計）と下のタブ・操作エリアは常に表示 — 理由：中だけスクロールする箱や畳む見出しは操作しにくかった
- 見出しは1行目に日付だけ、2行目に今週の合計（横スクロール） — 理由：取り組みが増えると日付の横では収まらない
- 今日｜明日｜週は細いレール（約28px）。週のカレンダー｜リストは下の「‹ 前の週｜カレンダー・リスト｜次の週 ›」の1段 — 理由：切り替えは横スライドが主。上は片手で届かない
- しおりタブは「組んで、始める」場所に絞る。＋ メモ（取り組みタブのメモ箱から）と ＋ 測る（記録タブの線グラフの横へ）は外した。数値型の中身は、測りたい数字が出てきたときに議論する — 理由：性質の違う操作が並んでいた
- その場の5分は「始める」側へ：今日だけ、次の行き先があれば「5分だけ始める」の真下に「▶ ほかのことを5分」、なければ主な操作が「何か5分だけ始める｜今日の振り返り」。始めた時刻にカレンダーへ小さな「▶ 名前」の印（札にしない・合計に入れない） — 理由：仕事でもプライベートでも始めるきっかけを作る機能で、カレンダーとつながって見えなかった。会議などの予定は入れないが、始めたことは印として残してよい
- 済・ここまでを押させる仕組みは作らず、自動で終える：次を始めたら前は終わる、予定の終わり時刻で終わる、その場の5分は30分。自動で終えたものは「始めた」扱いで、済は振り返りの答え合わせで付けられる。催促の通知はなし — 理由：作業の終わりに毎回押すとは限らず、押さないと次の行き先に進めなかった
- 今日・明日・週は、見出し（タイトル1行 17px＋今週の合計の1行）と下の操作エリアの形・文字の大きさをそろえ、画面のどこでも横スライドで切り替える（ページをめくる動き。ボタンでも同じ）。データは切り替えで読み直さない。見出しの日付は0埋め（11/09（月）、等幅の数字） — 理由：切り替えでチラつく・かくつく・幅が動くのが気になった
- 昨日の答え合わせは見出しに出さず、振り返りのボタンに点・シートのいちばん上に出す。主な操作に「今日の振り返り」を出す日は＋ボタンの段に「振り返り」を出さない — 理由：見出しがばらつく・同じボタンが2つ並んでいた
- この日だけの予定は、左の固定の列の空いた所をタップして足す。「固定 ▾」と「固定｜取り組み」の段はなくし、外した固定は点線で残してタップで戻す。休日として扱うは見出しの日付から開く日のシート（2026-11-09） — 理由：カレンダーを広く、固定の操作は直接触るほうが分かりやすい。いつもの固定・予定の長さは「開始〜終わり」で選ぶ（16時間まで、翌日にまたがってよい） — 理由：上のボタンは片手で届かない。仕事や睡眠が180分では足りなかった
- 日の区切りは朝4時のまま。0時〜4時は「明日」のカレンダーに「いま」の線を出し、空きもいまより後だけ — 理由：夜中に組んでも計画がずれないようにしつつ、実際の時刻を見せる
- タブは しおり／記録／取り組み／設定。記録＝眺める（週の7マス・やった時間の横棒・8週の棒・始めた回数・進み具合）、取り組み＝決める・直す（削除・種類変更あり） — 理由：作業と振り返りを分ける。円グラフは比較しにくいので使わない
- 済の時刻はカレンダーに出さずスタンプだけ — 理由：小言にしない
- ペナルティ・ストリークは入れない — 理由：要件メモの核（小言はスルーされる）
- iPhone と iPad は暗号化したまま同期。項目ごとに後から変えた方を残す。開いた時と保存のたびに同期 — 理由：中身をサーバーに読ませない
- 始める瞬間の対策は「5分だけ始める」「前の晩の準備」 — 理由：最初の一手だけでは SNS・漫画との綱引きに勝てない
- 5分だけ始める：画面のタイマーは置かない（スマホを見続けると綱引きの相手に近づく）。5分後の知らせは Web プッシュ（Apple Watch に届く）、集中モードはショートカット「しおり5分」（1行だけ） — 理由：ショートカットのリマインダー方式は iOS で動かなかった。戻り先指定は Safari が開くので使わない
- ここまで（やめる）：理由は任意のワンタップ（候補は設定で変更）、次はここからも任意 — 理由：5分でやめるのは約束どおりの成功。理由の必須は言い訳書きになる
- その場の5分（仕事など計画外）：回数だけ数え、取り組みの時間に入れない
- 視覚的に直感的にわかる：どの画面もこの物差しで判断する（全体を貫く方針に追加）
- 週の見通し：月〜日、カレンダーとリスト。決まっている予定と「この日にやること」の札だけで、時刻つきの行き先は前の晩 — 理由：週の計画は細かすぎ・途中で崩れる・忘れるで続かなかった。空いている日・次の休日・習慣の配分は知りたい
- 振り返りと続ける工夫：ふりかえり（記録タブの下、週ごと）、習慣型の変化メモと手応え（7マスの濃さ）、数値型（＋ 測る・線グラフ・目標は任意）、7マスの「前の晩に組んだ」、札のぶんを置く — 理由：責めずに積み上がりと変化を見せ、前の晩の手間を減らす。写真は容量と同期が重いので入れない
- メモ箱：思いつきを1行で入れる（しおりタブの「＋ メモ」からも）。候補には出ない。整える＝なりたい状態 → 種類 → ステップと最初の一手。整えたメモは「取り組みに」の印で残す — 理由：取り組みを作る手間が重く、やりたいことが置き去りになる
- 予定の開始時刻の通知：文面・タイミング（ちょうど〜30分前）・対象（すべて／最初だけ）を設定で選べる。文面に {行き先} を書いたときだけ名前をサーバーに置き、送ったら消す — 理由：中身をサーバーに読ませない方針と、名前が見えたほうが始めやすいことの両立
- プロジェクト型のステップは完了するまで何回もやる単位。済は「今回の分」で、ステップの完了は済のシートの「このステップは完了」（最初はオフ）か取り組みタブで。同じ行き先は1日に何回でも置け、札に「今日 2回」、予定に「1/2」 — 理由：作業ごとにステップを切ると手間がかかる。同じ作業を時間を分けてやることがある
- プロジェクト型に任意の期日（取り組みに1つ）。「あと○日」を淡く出し、週では期日の日に印。赤くしない・過ぎたら出さない・通知しない — 理由：危機感は燃料だが小言はスルーされる
- 固定が重なったら、後のものを右にずらして重ねる — 理由：この日だけの予定や時刻を動かした固定が重なると片方が見えなかった
- 「済をつける」ボタンの名前と置き場所は今のまま。ただし主な操作の段の上に「次：20:00–20:30 名前」を出し、済のシートにも時刻を出す — 理由：何時のどの予定に済をつけるのか分からなかった
- 予定の終わる時刻の通知（設定でオン、初めはオフ。文面は自分で、開始の通知と同じ時刻なら1通に） — 理由：終わったときに済をつけるきっかけにする。開始時刻の通知と同じ仕組みなので SQL・Edge Function の変更なし
- 時間は実際にやった時間（始めずに済にしたものは予定の長さ）、あわせて「始めた回数」 — 理由：着手が目的なので回数が本質
- 最初の一手はプロジェクト型なら前回の「次はここから」を自動で使う。きっかけは習慣型の「いつものきっかけ」だけ — 理由：日によって変わるものを毎回入れるのは負担

- **マージは本人が押す**。Claude の `gh api .../merge` は権限で止められる。PR を積み重ねると本人が順番を間違えるので、main 向けに1つずつ出す
